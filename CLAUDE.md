# CLAUDE.md — orientation for a fresh instance

The Coiled Compendium: a sourced Mythic+ reference for World of Warcraft:
Midnight, patch 12.1, Season 2. Published as a static site on GitHub Pages at
**https://samurairacy.github.io/coiled-compendium/**.

The site is `index.html` — ~991 KB, with CSS, JavaScript, the dungeon data and
every boss/banner image (base64 WebP) inline — plus `assets/icons/`, 228 small
JPEGs referenced by path. No build step in this repository, no dependencies, no
backend. The only external request is the Google Fonts stylesheet in `<head>`.

Start with README.md for what the site is, how it's sourced, and the licensing
position the project depends on.

## Editing index.html

**You may edit it.** Until 2026-08-16 this file carried a standing rule against
touching `index.html`, because it was generated by a build pipeline outside the
repository and direct edits were silently overwritten on the next regeneration.
That rule was retired deliberately — the repository is now where the site is
worked on.

What has not gone away is the underlying hazard: if a regenerated `index.html`
is ever dropped over the top of this one, anything added here by hand is lost
without a conflict to warn you. Two things currently live only in the repo copy:

- the `<link rel="icon">` / `<meta name="theme-color">` pair in `<head>`, and
- the `ICONS` map and its `abilIcon()` renderer (see below).

If a fresh build lands, re-apply those rather than assuming they survived.

## How the site works, to the extent this repository needs to know

- **Hash routing.** `#/dungeons`, `#/d/kings-rest/bosses`. `route()` runs once
  at script end and again on every `hashchange`, reading `location.hash` each
  time — which is why a deep link survives a reload on a static host with no
  rewrite rules. Nothing about the deploy may break this.
- **Eight dungeons, 30 encounter cards, 336 abilities.** A dungeon's `bosses:`
  field is the advertised boss count and is deliberately *not* the length of its
  `encounters` array — King's Rest declares 4 and carries 6. Sum `encounters`
  for the real figure; the README's "30" comes from there.
- **The homepage status line computes live** against the Season 2 start of
  18 Aug 2026: it counts down before that date and reads "Season 2 is live —
  week N" after it. A homepage that looks stale is usually just the calendar.
- **Ability icons** are keyed by ability *name*, not by ID. `ICONS` maps a name
  to a Blizzard icon slug and `abilIcon()` renders `assets/icons/<slug>.jpg`.
  259 of the 329 distinct names resolved against Wowhead's spell database; the
  other 70 are new Midnight content Wowhead has no entry for, or are not
  abilities at all (adds and structural notes sitting in the same arrays).
  **A name absent from `ICONS` renders an empty box of identical size, not
  nothing** — drop the spacer and every unmatched title jumps a glyph's width
  left of the column. Matching is by exact name, so renaming an ability in
  `DUNGEONS` silently costs it its icon; update both together.

## Repository conventions

- **`docs/` is git-ignored.** This repository is public. Working notes, briefs
  and anything not meant for publication live there and are never committed.
  Treat that as the default home for scratch material.
- **Nothing personal in tracked files.** No real names, no email addresses, no
  local filesystem paths. Commits are authored under the GitHub noreply address.
- **Stage explicit paths; never `git add -A`.** `docs/` is ignored, but a blanket
  add is still how unrelated work ends up in a mislabelled commit.

## Deployment

GitHub Pages, **deploy from a branch**: `main`, folder `/ (root)`. Pushing to
`main` publishes. There is no CI and no Actions workflow — the deploy is
GitHub's own Pages builder.

- `.nojekyll` stops Jekyll processing. Keep it: it costs nothing, and Jekyll has
  opinions about files whose names begin with an underscore.
- `.gitattributes` pins `*.html text eol=lf` so a ~2,350-line single-file diff
  stays readable on Windows. The source file is already pure LF.
- `assets/icons/` ships as 228 loose JPEGs (~411 KB) rather than more inline
  base64. Deliberate: they are cached per-file, fetched in parallel, and
  `loading="lazy"` means a dungeon page pulls only the dozen-odd it shows.
  Inlining them would have added ~550 KB to a payload every visitor downloads
  before the page renders, to save requests nobody was waiting on.
- No `CNAME` — no custom domain as of 2026-08-16.
- No bare `LICENSE` file, deliberately. The repository mixes original writing,
  Blizzard-owned game data and Blizzard imagery, so a blanket MIT or CC grant
  would claim rights the project doesn't hold. The README's *Licensing and
  attribution* section is the licence position. Don't "fix" this by adding one.

## After any change that reaches the live site

Load the published URL and check, in this order — these are the checks that have
actually caught things:

1. It renders: dark theme, serif headings, serpent mark top-left. Not a file
   listing, not a blank page.
2. Boss and banner images appear (~700 KB of the payload is inline base64).
3. **Deep link survives a reload.** Open
   `…/coiled-compendium/#/d/kings-rest/bosses` and hit refresh. It must land on
   King's Rest → Bosses. This is the check most likely to break on a static
   host.
4. The dungeon switcher moves between dungeons and keeps the current tab.
5. Search opens with `/` and returns results.
6. No console errors.

## Corrections and issues

Issues are enabled on purpose — the site is explicitly about surfacing where
sources disagree, so corrections are the point. Wikis, Projects and Discussions
are off.
